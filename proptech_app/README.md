# PropTech App — Frontend (Flutter)

Buyer/Tenant app scaffold. Feature-first architecture, Riverpod for state management, GoRouter for navigation.

## ⚠️ First-time setup (important)

This zip contains only `lib/`, `pubspec.yaml`, and assets — the platform folders
(`android/`, `ios/`, `web/`) need to be generated by Flutter itself on your machine.

1. Extract the zip and open the folder in VS Code.
2. Open a terminal in the project root and run:
   ```bash
   flutter create .
   ```
   This generates the `android/`, `ios/`, `web/`, `windows/`, `macos/`, `linux/` folders
   without touching your existing `lib/` or `pubspec.yaml`.
3. Install dependencies:
   ```bash
   flutter pub get
   ```
4. Run the app:
   ```bash
   flutter run
   ```

## Project structure

```
lib/
├── main.dart              # entry point
├── app/
│   ├── app.dart            # root MaterialApp widget
│   ├── router/              # GoRouter routes + route name constants
│   └── theme/                # colors, text styles, spacing, ThemeData
├── core/
│   └── widgets/             # reusable widgets (buttons, text fields, property card)
├── features/
│   ├── auth/                 # splash, login, register, role selection
│   ├── home/                 # home screen (Buy/Rent toggle, search, listings)
│   ├── properties/           # property model, dummy data, detail screen
│   ├── favorites/, search/, visits/, chat/, owner/, profile/  # placeholder screens
```

## Connecting to the real backend later

All dummy data lives in `lib/features/properties/models/property.dart` (`dummyProperties` list).
When the backend is ready:
1. Add a `PropertyApi` class under `features/properties/data/` using `dio` (already in pubspec.yaml).
2. Replace `dummyProperties` usage with a Riverpod `FutureProvider`/`AsyncNotifier` that calls the API.
3. Keep the `Property` model fields aligned with the backend's JSON response.
